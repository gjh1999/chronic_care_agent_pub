## 1. 项目概述

### 1.1 目标

为慢性病管理 Agent 开发患者端微信小程序,完成 MVP 闭环:**微信登录 → 对话式记录/建议/计划/提醒 → 健康数据页面化查看与管理 → 个人资料**。

### 1.2 范围(本期必须完成)

| 模块 | 内容 |
|------|------|
| 登录 | 微信一键登录(wx.login → code → 后端换 JWT)、退出登录、登录态持久化与失效跳转 |
| 对话 | 与 Agent 对话:记录、建议、计划两阶段确认(confirm / reject / modify)、直接提醒;消息历史展示 |
| 健康记录 | 手动录入血糖/血压/体重/症状、列表分页与筛选、删除 |
| 趋势统计 | 血糖/血压趋势图表(数据来自 GET /health/stats) |
| 计划 | 待确认 / 进行中 / 历史 三类列表、计划详情、归档 |
| 提醒 | 提醒列表、手动创建、取消 |
| 我的 | 个人资料查看与编辑(性别/出生日期/慢病标签) |

### 1.3 非目标(本期不做)

- 医生端、处方/诊断相关 UI
- CGM 等设备直连页面
- 消息推送订阅的完整配置(页面做,真实推送依赖后端 worker + 模板,见风险)
- 公众发布所需的运营/合规流程(体验版先行)

### 1.4 验收标准

- 一条命令启动后端(uvicorn :8000)+ 微信开发者工具导入项目,可完成:登录 → 对话记录一条血糖 → 查看记录列表与趋势 → 生成并确认一个计划 → 查看计划提醒 → 取消一条提醒 → 编辑资料
- 后端返回 `waiting_confirmation` 时前端正确渲染计划卡片,confirm 后会话状态回到 active
- 断网/接口错误时页面有明确提示,不白屏、不丢输入
- 全部页面在 iPhone SE(小屏)与主流安卓机上布局正常

## 4. 核心模块设计

### 4.1 请求封装 `utils/request.js`

```js
// 统一处理:baseURL、Bearer token、code≠0 报错、40002 清 token 跳登录、超时
request({ url, method, data, header })
```

- 响应契约:`{code, data, message, request_id}`;`code===0` 成功,否则 toast `message`
- `code===40002`(认证失败):清 token → 跳 `/pages/login/login`
- 写操作(记录/提醒/确认)自动携带 `Idempotency-Key`(uuid),防止小程序重试产生重复副作用

### 4.2 登录态

1. 启动:`uni.getStorageSync('token')` 存在 → 直接进 tab;不存在 → login 页
2. login 页:`uni.login()` 拿 code → `POST /api/v1/auth/wechat-login {code}` → 存 `access_token`
3. 每次启动后台静默 `GET /api/v1/auth/userinfo` 校验 token 有效性,40002 则重新登录
4. 我的页提供"退出登录" → `POST /api/v1/auth/logout` + 清本地 token

### 4.3 对话页(核心复杂度所在)

**状态机**:

```
idle → sending(loading,可长至 2-3 分钟) → completed | waiting_confirmation → resume → completed
```

- 会话管理:本地持久化 `conversation_id`;无则首次发消息前 `POST /conversations` 创建
- 发送消息:`POST /conversations/{id}/messages {content}`;loading 期间显示"思考中…"(真实 LLM 实测 15s~190s,必须给足等待反馈,禁止让用户误以为卡死;超时按 300s 处理)
- `status=waiting_confirmation` 时渲染**计划确认卡片**:
  - 展示 `plan` 计划项列表(时间/内容)
  - 三个按钮:确认 / 拒绝 / 修改(修改弹出输入框)
  - 调 `POST /conversations/{id}/interrupts/{interrupt_id}/resume {action, revision, modification?}`
  - 409(revision 冲突)提示"计划已变化,请刷新"
- 消息对展示:用户消息右、助手消息左;`final_response` 为助手文本(含 🚨/✅/💡/📋/⏰ 前缀,原样渲染)
- 紧急内容(`final_response` 含 🚨)用红色高亮卡片样式

### 4.4 健康记录页

- 列表:`GET /health/observations?page_no&page_size&metric_type`,上拉加载分页
- 录入:按 metric_type 切换表单(血糖=单值+单位+时段;血压=收缩压/舒张压;体重;症状文本),提交 `POST /health/observations`(source=manual,measured_at 客户端时间)
- 删除:长按/左滑 → 二次确认 → `DELETE /health/observations/{id}`
- 趋势入口 → stats 页:`GET /health/stats?metric_type=blood_glucose|blood_pressure`,ECharts 折线图,标注正常区间(血糖 3.9-7.8 / 血压 140-90)

### 4.5 计划页

- 三个 tab:`GET /plans?status=draft|confirmed|archived`(draft 即"待确认",但注意:草稿的确认在对话页完成,计划页 draft 列表用于跳转回对应会话或提示"请在对话中确认")
- 详情:计划项时间轴展示
- 归档:`POST /plans/{plan_id}/archive`(已确认/进行中才可)

### 4.6 提醒页

- 列表:`GET /reminders`(展示 next_run_at、状态 scheduled/sent/cancelled)
- 手动创建:`POST /reminders {title, schedule_rule:{time,date}, timezone:"Asia/Shanghai", channel:"in_app"}`;时间选择用 picker(日期 + 时分),前端把用户选择转成 `HH:MM`/`YYYY-MM-DD` 传给后端
- 取消:`POST /reminders/{id}/cancel`
- 注意:后端对无法解析的时间返回 422,前端表单约束(picker 选择)天然规避

### 4.7 我的页

- `GET /me` 展示性别/出生日期/慢病标签;`PUT /me` 编辑
- 免责声明入口:健康管理建议不替代医生(合规要求)

## 5. 接口对接契约(与当前后端一致)

前缀 `/api/v1`,除登录外全部带 `Authorization: Bearer {token}`。

| 模块 | 方法+路径 | 请求要点 | 响应要点 |
|------|-----------|----------|----------|
| 认证 | POST `/auth/wechat-login` | `{code}` | `data.access_token` |
| 认证 | GET `/auth/userinfo` | — | `data.user_id, role` |
| 认证 | POST `/auth/logout` | — | — |
| 对话 | POST `/conversations` | `{title?}` | `data.conversation_id` |
| 对话 | GET `/conversations/{id}` | — | `data.status, last_message_at` |
| 对话 | POST `/conversations/{id}/messages` | `{content}`(≤4000) | `data.status(completed/waiting_confirmation), final_response, workflow, interrupt_id, revision, plan_id, plan` |
| 对话 | POST `/conversations/{id}/interrupts/{interrupt_id}/resume` | `{action: confirm/reject/modify, revision, modification?}` | `data.status, action, plan, reminders` |
| 健康 | GET `/health/observations` | query:`metric_type?, page_no, page_size` | `data.{items,total,page_no,page_size}` |
| 健康 | POST `/health/observations` | metric_type + 对应数值字段 + measured_at(ISO) | `data.observation_id` |
| 健康 | DELETE `/health/observations/{id}` | — | — |
| 健康 | GET `/health/stats` | query:`metric_type`(必填) | 统计序列(实现联调时确认字段) |
| 计划 | GET `/plans` | query:`status?` | 数组:`plan_id, summary, status, revision, items[{content, schedule_rule}]` |
| 计划 | POST `/plans/{plan_id}/archive` | — | — |
| 提醒 | GET `/reminders` | query:`status?` | 数组:`reminder_id, title, schedule_rule, next_run_at, status` |
| 提醒 | POST `/reminders` | `{title, schedule_rule, timezone, channel}` | `data.reminder_id` |
| 提醒 | POST `/reminders/{id}/cancel` | — | — |
| 我的 | GET `/me` | — | `data.{gender, birth_date, disease_tags}` |
| 我的 | PUT `/me` | 上述字段 | 更新后资料 |

通用:错误 `{code, message, request_id}`;409=状态/版本冲突,422=校验失败,40004=不存在。

## 6. UI/UX 设计规范(慢病人群)

- **可读性优先**:正文字号 ≥16px(设计稿 32rpx 起),按钮 ≥88rpx 高,行距宽松
- **颜色语义**:
  - 红色 = 紧急/高危(🚨 消息、血压超标、计划确认的"拒绝")
  - 绿色 = 正常/完成
  - 主色蓝 = 品牌/可点击
- **单位标注**:血糖 mmol/L、血压 mmHg,录入表单固定单位提示
- **确认文化**:删除、拒绝计划、取消提醒等破坏性操作一律二次确认
- **医疗安全**:对话页常驻底部免责声明"建议不替代医生诊断";紧急文案红色卡片醒目;计划卡片必须完整展示全部计划项后再出现确认按钮
- **防误触**:确认按钮与拒绝按钮物理分隔(左右布局),拒绝为弱化样式

## 8. 里程碑与任务拆分

每个里程碑结束都达到**可演示**状态,并附验收点。

| 里程碑 | 内容 | 验收点 |
|--------|------|--------|
| **M1 工程骨架 + 登录**(1-2 天) | 项目初始化、tabBar 4 页壳、request 封装、登录流程、登录态守卫 | 微信开发者工具中完成登录→进入对话页→退出→自动回登录页;错误码 40002 自动跳登录 |
| **M2 对话闭环**(3-4 天) | 会话创建与持久化、消息发送/渲染、loading 状态、计划确认卡片(confirm/reject/modify)、409 冲突提示 | 与真实后端对话:记录一条血糖;生成计划→卡片出现→确认→状态回到 active;修改→新草稿卡片 |
| **M3 记录 + 趋势**(2-3 天) | 记录列表/分页/筛选、录入表单、删除、趋势页 ECharts | 录入 3 条血糖后列表与趋势正确;删除后消失;小屏布局正常 |
| **M4 计划 + 提醒**(2-3 天) | 计划三态列表与详情、归档;提醒列表/创建(picker)/取消 | 对话确认的计划出现在"进行中";归档后进"历史";手动创建"明早8点"提醒后列表显示次日时间 |
| **M5 我的 + 打磨**(1-2 天) | 资料查看编辑、免责声明、异常态/空态/加载态补齐、小屏与真机适配 | 全页面空态/错误态有提示;真机预览无布局问题 |
| **M6 联调与验收**(1-2 天) | 与后端 + 意图服务 + RAG 三服务联调全流程;对照 1.4 验收标准逐项过 | 1.4 全部通过;输出联调问题清单 |

## 10. 风险与依赖

| 风险 | 影响 | 应对 |
|------|------|------|
| 对话链路耗时 15s~190s(真实 LLM) | 用户以为卡死、重复点击 | loading 文案与动画、请求去重(发送中禁点)、300s 超时、可中断提示;后续后端若支持 SSE 再升级流式 |
| 意图服务(8020)不可用 | 对话整体失败 | 错误提示"服务暂不可用,请稍后再试";记录/计划/提醒页面是 REST,不受影响 |
| 微信域名校验 | 本地联调被拦截 | 开发者工具勾选"不校验合法域名";上线前配置 request 合法域名 |
| 提醒真实推送 | 前端无感知的 worker 投递(微信模板未配置) | 本期页面只管理提醒数据;推送触达列入后端待办,不影响前端验收 |
| ECharts 小程序版兼容 | 渲染失败/包体积 | 用 lime-echart 并压测;备选:canvas 手绘简单折线 |
| 健康数据合规 | 真实用户数据外发 | 联调阶段只用虚构数据;发布前完成隐私政策与授权 |
